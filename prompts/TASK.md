현재 시험 프로젝트 루트에서 작업하라. 시험이 제공한 루트 README.md는 읽기만 하고 수정·추가 기록·덮어쓰기·이동·이름 변경·삭제하지 마라. 코드·테스트는 기존 구조를 우선하라.
SPEC 요구사항 ID / 이번 목표:
필요한 SPEC 항목·파일·줄 범위:
수정할 코드·테스트 파일:
완료 조건 / 영향 범위·통합 검증 명령:
남은 시간:

이번 요구사항 하나에 대해 다음 순서를 수행하라.
1. SPEC의 근거·계약·Given/When/Then 인수 조건을 확인하고 변경된 명세를 먼저 반영한다.
2. 인수 조건을 검증하는 의미 있는 테스트를 작성·실행해 요구 동작 미충족으로 실패하는 Red를 확인한다.
3. 최소 구현으로 같은 테스트가 통과하는 Green을 확인한다.
4. 필요한 리팩터링 후 테스트를 재실행하고 영향 범위·통합 검증을 수행한다.
5. SPEC에는 확인된 답변·명세·결정만, STATE에는 ID·소유권·실제 실행 결과와 다음 작업만 갱신한다.

환경 오류를 Red로 간주하지 마라. 테스트가 이미 통과하면 그 사실을 기록하고 억지로 실패시키지 마라. TDD를 수행하지 못한 범위·이유·대체 검증은 명시하라.
필요한 질문은 수·횟수 제한 없이 그때마다 나에게 요청하라. 내가 담당자와 소통하고 답변을 전달한다. 답변에 의존하는 작업만 보류하고 확정된 독립 작업은 진행하라.
일상 보고는 요구사항 ID·변경 파일·실제 검증 결과·남은 문제 5줄 이내로 하고 필요한 질문은 별도로 제시하라. 변경된 항목만 기록하고 전체 문맥·명세·코드를 다시 출력하지 마라.
