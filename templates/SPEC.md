# SPEC — 요구사항·인수 조건의 기준
README와 사용자가 전달한 담당자 답변을 근거로 작성한다. 코드·테스트는 이 명세를 따른다. 근거가 충돌하거나 불명확하면 질문하고 해당 부분은 확인대기로 둔다. 변경된 항목만 갱신한다.

| ID | 필요한 동작 | 인수 조건: Given / When / Then | 근거: README 절·줄 또는 담당자 답변·시점 | 상태: 확정/확인대기 |
|---|---|---|---|---|
| R1 | | | | 확인대기 |

## 최소 계약 — 해당하는 항목만
| 관련 ID | 입력·출력 | 오류·경계 조건 | 권한 | 저장·변경 규칙 |
|---|---|---|---|---|
| R1 | | | | |

## 확인과 결정
- 질문·가정 / 관련 ID:
- 담당자 답변(사용자 전달) / 확인 시점 / 명세·구현 영향:
- 설계 결정: 관련 ID / 구조·책임 분리 / 선택 이유·제외한 대안:

질문은 필요할 때마다 사용자에게 요청하며 수·횟수를 제한하지 않는다. 사용자가 담당자와 소통해 답변을 전달한다. 답변에 의존하는 작업만 보류하고 확정된 독립 작업은 진행한다. 구현 진행·테스트 실행 기록은 STATE에서 ID로 참조하며 이곳에 중복하지 않는다.
