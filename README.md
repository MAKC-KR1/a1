# a1 — Codex 실기시험 경량 준비물

180분 서비스 개발 시험에서 **토큰 사용을 최소화하면서 필수 구현·검증·설명을 완료**하기 위한 짧은 지침과 빈 양식입니다. 시험 문제는 프로젝트 루트의 README.md로 제공된다는 조건을 전제로 합니다.

**공개 저장소: [MAKC-KR1/a1](https://github.com/MAKC-KR1/a1)**. 배포 리비전과 공개 확인 기록은 [PUBLICATION.md](PUBLICATION.md)에 남깁니다. 외부 자료로 사용할 때는 상세 가이드의 허용 범위를 확인하고 실제 사용한 커밋을 기록하세요. 활용하는 저장소는 2차 예선 결과 통지 전까지 공개 상태를 유지해야 합니다.

## 프로젝트 디렉토리 구조

시험 문제 `README.md`가 있는 **현재 프로젝트 루트에서** 이 저장소를 `a1/`로 가져옵니다. 별도 작업공간 경로 입력은 없습니다.

```text
현재 시험 프로젝트/
├── README.md                 # 제공된 시험 문제 — 원문 보존
├── AGENTS.md                 # 제공되어 있다면 기존 지침 유지
├── src/                      # 서비스 구현: 새 프로젝트의 기본 위치
├── tests/                    # 기능·경계·통합 검증: 새 프로젝트의 기본 위치
├── .exam/                    # 실제 시험 작업 기록
│   ├── STATE.md              # 요구사항, 질문·답변, 현재 작업, 결정
│   ├── SOURCES.md            # 사용한 공개 자료와 커밋
│   ├── AI_USAGE.md           # 주요 AI 활용과 사람의 확인
│   ├── EXPLAIN.md            # 최종 설계 설명과 예상 질문 답변
│   └── logs/                 # 필요한 상세 검증 로그만, 필요시 생성
└── a1/                       # 이 공개 준비물 저장소
    ├── README.md             # 준비물 사용법
    ├── START_PROMPT.md       # 시험 시작 지침
    ├── prompts/              # 필요할 때만 사용하는 작업·검토 지침
    ├── templates/            # .exam으로 복사할 빈 양식
    ├── LICENSE
    ├── PUBLICATION.md
    └── VALIDATION.md
```

`src/`, `tests/`는 기존 서비스 구조가 없는 경우의 기본안입니다. 제공된 프로젝트나 선택한 프레임워크가 `app/`, `pages/`, `backend/` 등 다른 구조를 사용하면 그대로 따르고 실제 위치만 STATE에 기록합니다. 기존 코드를 옮기거나 빈 폴더를 미리 모두 만들지 않습니다. `a1/`에는 시험 서비스 코드나 실제 기록을 작성하지 않습니다.

## 시험에서 사용하는 순서

아래 명령은 시험 문제 `README.md`가 있는 현재 프로젝트 루트에서 실행합니다. 셸 예시는 bash/zsh 기준입니다.

1. 상세 가이드가 허용한 방식으로 자료를 가져옵니다. 온라인 반입과 Git 사용이 허용되면 다음 명령을 실행합니다. 기존 `a1/`이 있으면 그 내용을 확인하고 사용합니다.

   ```sh
   git clone https://github.com/MAKC-KR1/a1.git a1
   ```

   네트워크가 차단돼 있으면 승인된 ZIP 반입 방식으로 현재 프로젝트 아래 `a1/`에 풉니다. 준비물 사용법은 `a1/README.md`, 시험 문제는 루트 `README.md`에 있어야 합니다.

2. 빈 작업 양식을 준비합니다. `cp -n`은 기존 기록을 덮어쓰지 않습니다.

   ```sh
   mkdir -p .exam
   cp -n a1/templates/*.md .exam/
   ```

   새 파일 반입이 제한되면 허용된 입력·메모 방식으로 같은 항목을 기록합니다. `.exam/logs/`는 상세 로그를 보관할 필요가 생길 때 만듭니다.

3. 사용한 저장소 URL·커밋·파일·MIT 라이선스를 `.exam/SOURCES.md`에 기록합니다. Git으로 가져온 경우 실제 사용 리비전은 다음 명령으로 확인합니다.

   ```sh
   git -C a1 rev-parse HEAD
   ```

   ZIP에는 `.git`이 없을 수 있으므로 다운로드한 실제 커밋·URL을 기록합니다. 확인할 수 없는 값은 미확인으로 남깁니다.

4. 제공된 Codex를 **현재 시험 프로젝트 루트**에서 사용합니다. [START_PROMPT.md](START_PROMPT.md) 내용을 첫 메시지로 전달합니다. 작업공간 경로를 입력할 필요가 없습니다. 전체 준비물 README와 모든 양식을 매번 읽히지 않습니다.
5. 필요한 확인은 사용자를 통해 담당자에게 요청합니다. 실제 답변과 구현 영향을 `.exam/STATE.md`에 기록하고 핵심 업무부터 구현·검증합니다.
6. 마지막에 실제 코드·검증 결과로 `.exam/EXPLAIN.md`를 완성하고 시험이 지정한 방식으로 제출합니다. 제출용 Git에는 필요한 서비스 코드·기록만 선택해 추가하고, 별도 Git 저장소인 `a1/`을 서비스 코드와 함께 일괄 추가하지 않습니다. 기록의 제출 여부는 시험 지침을 따릅니다.

원본 문제 README.md와 기존 프로젝트 지침은 보존합니다. 제공된 Codex 버전을 그대로 유지하며 업데이트하지 않습니다. 이 패키지는 Python, 추가 설치, 외부 API 키, Codex 설정 변경을 요구하지 않으며 서비스 구현 코드·모의 정답·별도 모델 실행기를 포함하지 않습니다.

## 담당자 확인이 필요할 때

원문과 확인된 답변으로 결정할 수 없는 사항은 **질문 수·횟수 제한 없이 필요할 때 사용자에게 질문**합니다. 사용자가 담당자와 대화하고 실제 답변을 AI에게 전달합니다. AI가 담당자 답변을 만들어 내거나 추측으로 확정하지 않습니다. 답변이 필요한 모호한 작업은 보류하고, 기다리는 동안 확정된 독립 작업을 계속합니다. 받은 답변과 그에 따른 결정만 STATE에 짧게 남깁니다.

## 토큰을 줄이는 운영 규칙

| 반복 비용 | 적용할 방법 |
|---|---|
| 여러 에이전트에 같은 명세·대화 복제 | 주 에이전트 1개가 기본. 독립 작업에만 보조 1개를 필요시 사용 |
| 매번 전체 저장소 읽기 | 시작에 문제·실행 설정 파악, 이후 파일 검색과 관련 구간만 읽기 |
| 장문 계획·보고·코드 재출력 | 한 작업씩 지시, 일상 보고는 변경 파일·검증·다음 조치 5줄 내, 필요한 질문은 별도 |
| 여러 문서를 매 작업마다 재생성 | STATE 한 파일의 변경된 항목만 갱신 |
| 같은 오류에 무작정 재시도 | 재현 입력·실제 로그·관련 코드로 원인을 좁히기 |
| 상시 리뷰·설명 에이전트 | 필요할 때 범위를 좁혀 검토하고, 최종 설명은 한 번 작성 |

한 작업은 하나의 완료 조건으로 묶습니다. 작은 수정마다 새 에이전트를 만들거나, 전체 기능을 한 번에 모호하게 요청하지 않습니다. 모델 응답이 실제 파일로 저장되면 같은 코드 전체를 채팅으로 다시 받지 않습니다.

검증은 변경에 영향을 받는 검사부터 실행하고, 제출 전 필요한 통합·핵심 시나리오 검증을 수행합니다. 토큰 절약을 위해 테스트를 생략하거나 실패 검사를 약화하지 않습니다. 짧은 프롬프트와 파일 읽기 범위는 운영 방침이며 제공된 Codex의 내부 컨텍스트 처리·캐시·과금량을 강제로 제어하는 기능은 아닙니다.

## 권장 모델과 사용 기록

시험 안내의 권장 표시명은 **6.1 Sol, 5.6 Terra, 6.0 Luna**입니다. 이름을 다른 모델 버전으로 바꾸지 않습니다. 이 안내만으로 모델별 토큰 효율·성능 순위를 판단할 수 없으므로 특정 모델이 더 적은 토큰을 쓴다고 단정하지 않습니다.

시험 환경에서 제공되는 권장 모델 중 검증된 한 모델로 시작하고, 동일 작업을 여러 모델에 반복해서 맡기지 않습니다. 전환은 구체적인 실패 원인이나 작업상 필요가 있을 때만 합니다. 모델 선택권·하위 에이전트 기능이 없다면 제공된 한 모델로 역할을 순서대로 수행합니다.

[AI_USAGE.md](templates/AI_USAGE.md)에 중요한 작업별 목적·모델·사람의 확인·실제 검증을 짧게 기록합니다. 토큰 사용량을 화면이나 로그가 제공하지 않으면 미제공으로 남깁니다. 숨겨진 사용량에 대한 정확한 최소값이나 절감률을 보장하지 않습니다.

## 시간과 설명

20분 요구사항 확인, 35분 실행 환경·계약, 80분 핵심 흐름, 125분 기능 추가 중단, 160분 제출 준비, 180분 제출 완료를 기준으로 삼습니다. 시간은 시험 타이머를 사용하고 필요할 때 남은 시간을 AI에 알려줍니다.

[EXPLAIN.md](templates/EXPLAIN.md)는 제출 직전에 실제 코드·검증 기록으로 채웁니다. 작업 중에는 STATE에 설계 선택과 근거를 짧게 남겨 최종 정리 때 전체 분석을 반복하지 않도록 합니다.

## 출처와 공개 상태

사용 자료는 [SOURCES.md](templates/SOURCES.md)에 URL·커밋·사용 파일·라이선스·직접 수정한 부분을 기록합니다. 공개 자료 활용 허용은 상세 가이드의 범위 안에서 적용됩니다. 공개라는 이유만으로 어떤 자료·반입 방식이든 허용된다고 가정하지 않습니다. 외부 결과물로 과제를 통째로 대체하지 않습니다.

공개 저장소에는 이 일반 지침·빈 양식만 게시합니다. 실제 시험 README, 담당자 대화, 해답, 제출물, 실행 기록은 포함하지 않습니다. 게시 준비 사항은 [PUBLICATION.md](PUBLICATION.md)에 정리했습니다.

Codex에서 AGENTS.md가 인식되며 다른 기록 파일은 선택적 운영 관례라는 점은 [OpenAI 공식 워크플로 문서](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex)를 참고했습니다. 이 경량 패키지는 기존 AGENTS.md를 수정하거나 별도 파일의 자동 로딩을 전제하지 않습니다. 시험 안내와 제공된 버전에서 실제 지원되는 동작을 우선합니다.
