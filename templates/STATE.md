- 문제 원본(프로젝트 루트 `README.md`) 시작 SHA-256 / 사용 명령: 미기록 — 도구가 없으면 확인 불가 사유 기록
- 선택한 모델(화면 표시 그대로):
- 현재 SPEC 요구사항 ID / 단계 / 다음 한 작업:

## 현재 요구사항의 실제 검증
| 단계 | 실행 명령 | 관찰 결과·근거 또는 미실행 이유 |
|---|---|---|
| Red: 요구 동작 미충족으로 실패 | | |
| Green: 최소 구현 후 통과 | | |
| Refactor: 정리 후 재검증 | | |
| 영향 범위·통합 검증 | | |
- 실패 재현·남은 문제:
- TDD를 적용하지 못한 범위 / 이유 / 대신 실행한 검증:

요구사항·담당자 답변·설계 결정은 SPEC에만 기록하고 여기서는 ID로 참조한다. 환경·설정 오류는 Red로 기록하지 않는다. 기존 구현으로 이미 통과한 테스트도 Red로 꾸미지 않는다. 상세 로그와 완료 이력은 필요시 별도 파일로 옮겨 보존하고 매번 입력하지 않는다.
